# Dirty-Flag Background Sync and Fresh-Load Snapshots Across Extension Contexts

In Manifest V3, the Sidebar UI, Popup UI, and Background Service Worker run in separate execution contexts with separate in-memory `CollectionStore` and `SearchEngineStore` instances backed by `chrome.storage.local`. When storage mutates, `initializeBackgroundSync` intentionally marks `sync_dirty = true` without starting a debounced background auto-sync timer, `createUnifiedBackup` forces a fresh `load()` from storage before constructing a Unified Backup, and pending changes are flushed on view/window close (`flushPendingSync`) or browser startup (`autoLoginAndSync`). This prevents a background timer with a stale in-memory store cache from running mid-edit and treating newly created items from another context as deleted during a three-way merge.
